## Contratos confirmados (fuente de verdad)

### P4 — Eliminación física de Producto
- **Roles**: Super Admin + Admin Comercial (`products:write`).
- **ACL**: `manage` sobre el producto/lista.
- **Confirmación**: `confirm: true` obligatorio en body.
- **Clave maestra**: Obligatoria si el producto tiene datos asociados (precios, imágenes, stock, auditoría, órdenes de compra referenciadas). Flujo: 409 sin clave → 403 clave incorrecta → 200 con clave correcta.
- **Auditoría**: `action='delete'`, `entity='Product'`, `oldValues` con resumen (sku, name, lifecycleStatus, flags) ANTES del hard delete.

### P6 — Scheduler interno
- **Tecnología**: `@nestjs/schedule@6.1.3`, `ScheduleModule.forRoot()` en `AppModule`.
- **Cron**: `@Cron(CronExpression.EVERY_MINUTE)` en `ProductsService.handleLifecycleTick()`.
- **Acciones**:
  - SCHEDULED → PUBLISHED cuando `publishAt <= now` (re-valida checklist de publicación).
  - PUBLISHED → DRAFT cuando `unpublishAt <= now` (reason `'auto'`).
- **Idempotencia**: lock en memoria + query condicional (`where lifecycleStatus + fecha`) + re-chequeo en `doTransition`.
- **Fallback**: lazy read-repair (`autoUnpublishDueProducts`) **mantenido** como red de seguridad temporal.

## Arquitectura actual (dual-write temporal)

| lifecycleStatus (fuente) | Espejo legacy (dual-write) |
|-------------------------|----------------------------|
| DRAFT | `isActive=true`, `publishStatus='borrador'` |
| READY | `isActive=true`, `publishStatus='listo'`, `publishAt=null` |
| SCHEDULED | `isActive=true`, `publishStatus='listo'`, `publishAt=fecha` |
| PUBLISHED | `isActive=true`, `isVisible=true`, `publishStatus='publicado'`, `publishedAt=now` |
| HIDDEN | `isActive=true`, `isVisible=false`, `publishStatus='publicado'` |
| DISCONTINUED | `isActive=false`, `publishStatus` conservado |
| ARCHIVED | `isActive=false`, `isVisible=false`, `publishStatus='archivado'` |

**Las lecturas de negocio** (listados, filtros, trending, lazy repair) **migrarán progresivamente a `lifecycleStatus`** en la Etapa 8.1. Hasta entonces, el dual-write es obligatorio y las columnas legacy no se tocan.
